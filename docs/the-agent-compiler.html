§ Overview

A compiler

Point ADAS-CC at any repository and it produces a complete Claude Code project configuration — a CLAUDE.md, role-based subagents, slash commands, reusable skills, and enforcement hooks — tailored to that repo's stack.

It does not touch your application code, and it does not perform your coding task itself. It runs exactly once per invocation, reasons about what your repository needs, and hands the result to a human for review before anything is written.

The distinction that matters

ADAS-CC's own internals are a five-node LangGraph pipeline running in one Python process. The planner / implementer / reviewer / tester agents it writes to .claude/agents/ are a separate system — plain markdown files that Claude Code reads on every future session in the target repo. The two are connected by one act (a file write), never by a shared runtime.

§ 01 — Orchestration

Five deterministic stages, one optional LLM call

The generator itself is a StateGraph over a plain AdasState TypedDict, compiled with a MemorySaver checkpointer and driven by a thread_id the CLI mints per run. Only one stage — design — ever calls out to an LLM; everything else is ordinary, reproducible Python.

01 · nodes/scanner.py

scan

Heuristic, dependency-free repo analysis: languages, frameworks, package managers, test tooling, CI, entry points, recent git history, and any existing .claude/ config. Read-only.

02 · nodes/designer.py

design

Calls Claude via ChatAnthropic.with_structured_output(), constrained to the DesignModel schema. With no ANTHROPIC_API_KEY, falls back to a rule-based planner → implementer → reviewer → tester default.

03 · nodes/generator.py

generate

Pure rendering: turns the DesignSpec into concrete ProposedFile entries — path, content, kind — and computes a unified diff against anything already on disk.

04 · nodes/approval.py

approve

A LangGraph interrupt(). The graph pauses; the CLI shows the file tree and diffs; a human replies approve, view, revise, or reject — resumed via Command(resume=...).

05 · nodes/writer.py

write

Creates directories, writes only the approved files, and marks generated shell hooks executable. Never deletes a file it didn't propose.

§ 02 — A layer boundary

One process writes the files; a different one reads them

It's easy to conflate "multi-agent" here with the LangGraph nodes above. They aren't the same thing. The graph in §01 runs once, inside adas-cc, and terminates. What it leaves behind — CLAUDE.md and .claude/* — is read by Claude Code itself, in an entirely separate process, on every session afterward, for as long as the target repo exists.

This is also why regeneration is safe: the scanner detects an existing .claude/ tree, flips into update mode, and the designer is told what already exists so it proposes gaps rather than duplicates — see §04.

§ 03 — What gets generated

The agent system that lives in your repo

The default (offline, no API key) design produces a four-agent chain with an explicit handoff order. The LLM-driven designer is free to propose a different shape, but it's constrained to the same SubagentModel schema — name, description, tools, model, a full system prompt, and handoff_to.

AgentJobToolsHands off to
plannerRead the repository, identify conventions and risks, produce a concrete plan.Read, Grep, Glob, Bashimplementer
implementerApply the plan with focused code changes.Read, Write, Edit, Grep, Glob, Bashreviewer
reviewerReview the current diff for correctness, security, readability, coverage.Read, Grep, Glob, Bashtester
testerAdd or update tests and run the project suite.Read, Write, Edit, Bash, Grep, Glob— end of chain

Each agent is a plain markdown file with YAML frontmatter — only name and description are required by Claude Code, but ADAS-CC also sets tools and model so every role runs at minimum privilege and the right cost/quality tradeoff.

PrimitiveLocationWhat ADAS-CC writes there
Project memoryCLAUDE.mdStack summary, key commands, conventions — loaded into every session and subagent.
Subagents.claude/agents/<name>.mdname / description / tools / model frontmatter plus a full system-prompt body.
Slash commands.claude/commands/<name>.mdOne-shot prompts (/plan, /review) with argument-hint and allowed-tools.
Skills.claude/skills/<name>/SKILL.mdReusable multi-step procedures Claude discovers and invokes on its own.
Hooks.claude/settings.jsonPreToolUse / PostToolUse enforcement — e.g. auto-format after an edit.
Why files, not the Agent SDK's agents param

Markdown agents are checked into version control and reviewable in a normal PR; they behave identically whether Claude Code is run interactively or headlessly; and programmatically-defined agents take precedence over filesystem ones with the same name, so nothing here conflicts with an SDK-based setup added later.

§ 04 — Update mode

Regeneration never overwrites blind

If .claude/ already exists in the target repo, the scanner flags is_update_mode and records what's already there in existing_claude_config. The designer is told, so it proposes gaps instead of duplicates; the generator diffs every proposed file against the current one on disk. Hook entries in settings.json are merged in — non-hook settings are left untouched — and nothing is ever deleted that ADAS-CC didn't itself propose.

$ adas-cc scan ./payments-service

  Repo Scan
  Primary language     python
  Frameworks           fastapi
  Test frameworks      pytest
  Package managers     uv
  CI                   github-actions
  Files scanned        142
  Update mode          yes (.claude/ already exists)

  Proposed Files
  Path                                 Kind          Status
  CLAUDE.md                            claude_md     unchanged
  .claude/agents/planner.md            agent         new
  .claude/agents/security-reviewer.md  agent         new
  .claude/commands/plan.md             command       new
  .claude/skills/run-tests/SKILL.md    skill         new
  .claude/settings.json                hook_settings changed

  [a]pprove / [v]iew a file / [r]evise with feedback / [x] reject: _

a writes every proposed file · v opens one file's preview and diff · r sends written feedback back to design for another pass, capped at three rounds · x exits without writing anything. --auto-approve skips the pause entirely for scripted or CI-style runs.

§ 05 — Running it

Quick start

$ pip install -e .
$ # optional — omit to use the offline rule-based designer
$ export ANTHROPIC_API_KEY=sk-ant-...
$ adas-cc scan /path/to/your-repo

# skip the interactive review, write immediately
$ adas-cc scan /path/to/your-repo --auto-approve

# pick the designer model explicitly
$ adas-cc scan /path/to/your-repo --model claude-opus-5

Requirements: Python 3.10+, and a target repo — a git history isn't required, but the scan report is richer when recent commits are available. The ANTHROPIC_API_KEY is optional and should never be committed.

Apache-2.0 Generated .claude/ files, reviewed by a human, checked into version control like any other change.
